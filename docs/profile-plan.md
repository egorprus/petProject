# План: страница профиля пользователя

Этапы идут по порядку, каждый следующий опирается на предыдущий.

## 1. Свой профиль с редактированием — готово

- Страница `/profile` (только для авторизованного пользователя).
- Просмотр: аватар, имя, логин, почта, дата регистрации.
- Редактирование имени, почты и аватара (почта — новое необязательное поле `email`, уникальное).
- Смена пароля (с проверкой текущего).
- Ссылка в хедере ведёт на эту страницу.

Аватар хранится в MongoDB (`avatarData` / `avatarContentType`, `select: false`), а не на диске:
файловая система Render временная и очищается при деплое/рестарте. Загрузка — `POST /auth/me/avatar`
(до 1 МБ, PNG/JPEG/WEBP/GIF), отдача — публичный `GET /user/:id/avatar`.

## 2. Публичная страница `/u/:login`

- Другие пользователи видят имя, аватар, дату регистрации.
- Серверный эндпоинт поиска пользователя по логину (только публичные поля).
- Если открыт свой профиль — показывать кнопку перехода к редактированию (этап 1).
- Опционально: ссылка на расшаренный список фильмов, если `movieShareToken` задан.

## 3. Личный дашборд

- Сводка по разделам на странице профиля: количество фильмов (просмотрено / в планах / избранное),
  ближайшие события календаря, итог банка за текущий месяц.
- Серверный эндпоинт агрегированной статистики, чтобы не тянуть все записи на клиент.

## 4. Настройка страниц в навигации — готово

Пользователь выбирает, какие разделы (Content, Bank, Calendar, Training, Movies) показывать в хедере.
Отдельной страницы `/settings` нет — блок «Страницы в меню» (`PagesSettings`) стоит на странице профиля.

- **Источник списка — сервер.** Полный список страниц задан только в `server/constants/pages.js`
  (`PAGES` — `{ key, name }`, `key` совпадает с роутом клиента). На клиенте своего списка нет, поэтому
  менять его в двух местах не нужно. Новая страница = строка в `PAGES` + роут на клиенте.
- **Хранение.** В `User` поле `hiddenPage: string[]` (по умолчанию `[]`, старым пользователям миграция
  не нужна). Сохраняется через `PATCH /auth/me` `{ hiddenPage }`: валидируется как массив ключей из
  `PAGE_KEYS`, дубликаты убираются.
- **`GET /pages`** (под авторизацией): без параметра — весь список (для настроек),
  `?visible=true` — только не скрытые текущим пользователем (для хедера). Видимые страницы специально
  не добавлены в данные юзера, чтобы не возить их в каждом ответе.
- **Клиент.** `profileApi.getPages(visible?)` и `profileApi.updateHiddenPages(hiddenPage)`.
  Хедер запрашивает `getPages(true)` после авторизации и перезапрашивает при изменении
  `hiddenPage` в сторе — после сохранения настроек меню обновляется сразу.
- **UI.** Чекбоксы-плашки с подсветкой отмеченных. Общий `CheckboxField` переделан на свой стиль
  (20px, зелёная заливка с галочкой) — затронул также чекбоксы в календаре и фильмах.

- **Прямой URL закрыт.** Роуты скрываемых страниц обёрнуты в `HiddenPageGuard`
  (`client/src/app/HiddenPageGuard.tsx`): если страница в `hiddenPage`, редирект на `/profile`.
  Закрыто только на клиенте — API разделов (`/bank-records`, `/movie-records` и т.д.) не блокируется,
  скрытие страницы — настройка интерфейса, а не права доступа.
- **Пустое меню допустимо** — можно снять все галочки, профиль остаётся доступен через аватар в хедере.
- Старый `NAV_LIST` из `client/src/shared/constants/constants.ts` удалён.

## Техдолг

- `POST /upload` (картинки для постов) не работает: папки `uploads` нет и multer её не создаёт (ENOENT → 500),
  `/uploads` не раздаётся статикой (catch-all отдаёт `index.html`), а на Render файлы всё равно не переживут
  рестарт. На клиенте сейчас не используется — починить по схеме аватаров или удалить.

По порядку важности:

1. **Подмена владельца записи.** `update` в `BankController`, `MovieController` и `CalendarController`
   делает `findOneAndUpdate({ _id, user }, req.body)` — тело пишется целиком, и `PATCH` с
   `user: <чужой id>` переносит запись другому пользователю. Брать из `req.body` только разрешённые
   поля, как в `create`.
2. **Валидация на сервере.** У `bank-records`, `calendar-events`, `movie-records` её нет совсем.
   `loginValidation` написан, но не подключён к `POST /login`.
3. **Обработка ошибок.**
   - `PostController.remove` — в `catch` только `console.log`, ответа нет, запрос висит.
   - В `getMe` / `getUser` скопировано сообщение «Не удалось зарегистрироваться».
   - `checkAuth` отвечает 403 на отсутствующий/невалидный токен — по смыслу 401.
4. **Мёртвый код.** Страница Training — заглушка; неиспользуемый импорт `validationResult`
   в `UserController`.
5. **Типы и тесты.** `tsc --noEmit` падает с ошибками в `PostActionAdd`, `Collapsible`, `SelectField`,
   `Header` — Vite при сборке типы не проверяет. Починить и добавить `tsc --noEmit` в `build`.
   Тестов нет вообще.
6. **Безопасность (мелочи).** JWT на 30 дней в `localStorage`; `cors()` открыт для всех доменов
   (не нужен, если клиент и сервер на одном домене); нет rate limit на `/login`.
